# Project Notes System

Use this skill when the user wants help organizing scattered project notes, especially across Notion, plain text files, email drafts, documents, or other fragmented storage.

## Workflow

1. Separate the system into four functions: capture, project home, archive, and review.
2. Recommend one capture inbox for unfinished thoughts, links, fragments, meeting notes, and loose ideas. Do not organize while capturing.
3. Create or recommend one project index containing: project name, status, home location, next action, and last touched date.
4. Assign one canonical home per active project. Treat that note, page, folder, or file as the source of truth.
5. Use a standard project-note shape: Outcome, Current state, Next actions, Decisions made, Open questions, Links / references, and Log.
6. Convert email drafts into inbox items or project-home content. Do not let email drafts become the long-term notes system.
7. Establish a weekly consolidation routine: empty the inbox, update the project index, archive inactive projects, and choose next actions for active projects.
8. Start with an inventory: list each project, where its notes currently live, and whether it is active, waiting, parked, archived, or dead.

## Guidance

Favor a lightweight dashboard/index in a tool like Notion and repo-local plain text only when it is useful for technical notes close to code. Keep the system boring, consistent, and easy to review.
