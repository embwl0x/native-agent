# Proof-of-Life Loop

Use this when the user feels their project is not going anywhere, especially in infrastructure-heavy systems with agents, prompts, bridges, memory, UI, background services, or routing layers.

## Rule
Do not start by rethinking the whole project. Pick one visible end-to-end loop that proves the system has a heartbeat.

## Workflow
1. Name the smallest product heartbeat in concrete terms.
   - Example: `User says something -> agent receives it -> routes context -> uses one capability -> answers in voice -> leaves a receipt`.
2. Treat that loop as the current truth test.
3. If it works, point out that the project has a visible proof of life and identify the next smallest strengthening step.
4. If it fails, debug the first broken handoff in the chain instead of expanding scope.
5. Keep emotional reassurance grounded in observable system behavior, not generic encouragement.

## Tone
Acknowledge the discouragement directly. Avoid dramatic life or strategy pivots. Frame the feeling as a starved feedback loop, not as evidence that the work is useless.
