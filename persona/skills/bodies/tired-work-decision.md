# Tired Work Decision

Use when the user is tired and deciding whether to keep working or rest.

Default recommendation: rest, especially if the user is already tired enough to ask.

Workflow:
1. Tell them directly to rest unless there is a truly urgent deadline or safety-critical reason to continue.
2. Have them write down the next 1-3 concrete actions they would take if they kept working.
3. If one small preparation task would make tomorrow easier, cap it at 10 minutes.
4. Explicitly discourage an open-ended “push through” loop.
5. Frame rest as the more effective option because tired work is usually slower, lower quality, and more costly than it feels.
