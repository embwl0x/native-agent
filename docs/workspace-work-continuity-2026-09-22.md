## Implemented contract

- **This work** keeps an explicitly authored continuation note with the existing
  desktop arrangement. A short preview stays visible during navigation; opening
  the work shows the complete note and kept places. Purpose, requirements and
  remaining editorial judgment can survive leaving the conversation.
- **Keep with this work** retains exact supported references independently of the
  rolling recent-place list. Files, sources, memories, skills, ongoing work and
  named conversations share this mechanism. Opening reads their canonical owner.
  References which cannot retain an exact reply selector are not broadened to a
  latest conversation. Browser references retain the address, never a live lease.
- **Focus on these places** removes unrelated recent-place clutter from this
  arrangement while preserving drafts. Thereafter, successful detail sources
  opened for this work stay attached automatically; lists and search results do
  not. Collection can be turned off and individual references removed. Capacity
  reports attention instead of silently dropping earlier sources.
- Discussing an explicitly selected source within named/noted work attaches the
  source and resolved conversation. An admitted send that throws still retains
  its exact recorded return route when the owner can resolve it. Unknown routes
  remain explicitly unattached; there is no resend or invented delivery.
- **Revise this file** opens the selected file with complete text already entered
  and the destination fixed. **Save revision** uses the ordinary write owner,
  checks the original content, and returns the actual readback. The guard survives
  saved drafts. A partial, changed, missing, binary or oversized source cannot
  become an unchecked replacement draft.
- The work retains its latest ordinary action outcome and observed readback.
  A complete saved-file read is compared with the submitted bytes in Swift, so
  Agent need not narrate a save receipt into the continuation note. Partial,
  missing or differing readback stays explicit. This single receipt is dated;
  it does not become a history index or a declaration that requirements are met.
- Find resolves short exact installed skill names/IDs to direct opening actions
  ahead of historical mentions. It reads only the existing metadata inventory;
  bodies stay lazy. At most three direct matches are shown, and an unavailable
  inventory is separate from a genuine no-match result.

These are navigation and draft features. The continuation note is Agent's
authored account, not another task ledger, memory authority or completion engine.
A returned review does not mean its advice was applied. A write receipt does not
mean requirements were met. Canonical owners, actual evidence and Agent's judgment
continue to determine those outcomes.

## Resource and permission boundaries

There are at most twelve kept references, a 4 KiB continuation note and one
bounded last-action receipt per
arrangement, within the existing twelve arrangements and 512 KiB desktop limit.
No index, background scanning, provider call, polling loop or loaded-source cache
was added. Old desktops decode the optional fields as empty. Corrupt storage
remains byte-preserved. New state is saved only when changed through the existing
owner. Saving or switching never resumes an action.

Revision reads are bounded to 64 KiB of complete UTF-8. The file owner compares
the expected SHA-256 and opened/named file identity immediately before its existing
atomic rename. This detects source conflicts; it is not atomic compare-and-swap
against an independently writing process. Existing file permissions and sensitive
path fences apply. Operator-disabled Mail/Messages/Contacts writes and human
Full Mac choices are unchanged. LM Studio and local-model work remain excluded.
