# NativeAgent 0.6.4

The agent grows into your apps. Tools, skills and senses are now one thing —
abilities — and the agent writes, checks and keeps its own.

## Abilities

- Tools, skills and senses are one idea with one lifecycle: propose,
  validate, keep, roll back, drop. They run on one JavaScript engine inside
  the app.
- Each ability is one file in the agent's abilities folder, with at most one
  previous version beside it for rollback. Dropping an ability deletes its
  file; nothing lingers in an archive or trash.
- Ask in plain words and the agent grows what it needs: a sense for a file
  kind it couldn't read, a tool that drives an app, a skill that strings
  tools together. Each new version is validated before it is kept; one that
  fails is discarded and the working version stays.
- Abilities can drive any scriptable Mac app by its bundle id, with a
  per-command timeout, and notice when an app's dialog is in the way.
- Every turn carries a short line of what the agent can do, so it knows its
  own abilities in a new chat. The abilities census lists them all.
- Your switches hold: an ability you turned off stays off until you turn it
  back on. An agent you marked trusted acts as you would; untrusted peers
  cannot change abilities.

## Works on smaller models

- A full plain-ask run on a small model drove fixes that help every model:
  malformed tool calls are repaired instead of dropped, a reply that
  announces work but makes no call is continued, stray tags no longer reach
  the reply, and a stalled stream is retried on evidence.
- Session summaries never fail a turn; a summary that can't be read is
  recorded and the turn goes on.

## Smoother

- The Mac app does less on its main thread: streaming a reply, switching
  chats, long transcripts, the rail pages and launch all redraw only what
  changed, and file reads and image decoding happen off the main thread.
- The iPhone app redraws less per keystroke and per streamed word.
- iPhone status (health, Desk, turn summaries) publishes again: the Mac's
  status saves were being deferred by the system while the app was in the
  background.

## Leaner

- About 25,000 lines of dead code, duplicate mechanisms and wasted work
  removed across the app, the engine and the iPhone app.
- Engine logic moved out of the window code and back into the engine, and
  the architecture check now keeps it there.
