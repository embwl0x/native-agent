# NativeAgent 0.4.6

This release is about memory that reads what you mean, turns that do not die,
and a shell that finally looks like the product it is.

## Memory

- A large sentence-embedding model (bge-large-en-v1.5, 1024 dimensions) ships
  inside the app and runs on the Neural Engine. Your memory store re-embeds
  itself once at first launch; the bundled MiniLM remains the floor.
- Recall asks every question in both voices, so a memory that names the agent
  answers a question that says "me", and the reverse.
- Committed memories say the thing itself: no dates, sources or ids in the text.
- The agent can walk, rewrite and forget its own memories, and rebuild its
  knowledge graph, with tools of its own.
- The knowledge graph is derived from the current rows: old imported nodes and
  edges are purged on rebuild, one node per name, and the name tagger no longer
  invents people from sentence-initial verbs.
- Six memory switches in Settings gate exactly what they name, and fail closed
  on an unreadable policy.

## Turns that keep going

- A provider failure mid-turn retries in place, up to ten times with backoff,
  with a visible "Reconnecting to the model" line on every surface. Tool
  results are never re-run.
- A dropped stream continues from what was already shown.
- A long tool loop trims its own working context before the model window fills,
  and again if a provider ever refuses the request as too long.
- Compaction keeps the whole earlier arc of a session; a compaction failure no
  longer ends the turn.

## The shell

- A wider rail with Chat, Today, Memories, Personality, Providers, Trust,
  Connectors, Diagnostics, Capabilities, Notifications, Desk, and Settings, with
  tabs inside each page for what belongs together.
- Settings on one page: everyday controls first, then a switch for every
  feature the agent carries.
- Provider pickers choose the provider first, then that provider's models,
  showing only providers that are connected.
- The transcript no longer pins the main thread on long conversations.

## Dark by default

- A fresh install opens in dark mode. Light remains one switch away in
  Settings and in the detached chat window.
- A pinned session stays in the pinned list when another chat is selected,
  and the "working" card floats above the composer instead of covering it.

## Three bug sweeps

Three read-only sweeps over every area of the app, each finding verified
against the code before it was fixed and every fix reviewed. About 275 fixes
landed. The ones you can see:

- iPhone: every pinned session you can select has its history, newest first,
  under a measured size budget; a conversation opened from a notification is
  not bounced back to the main chat; overlapping session-list reads can no
  longer restore an older list; turning spoken replies off stops the current
  utterance; a re-paired phone recovers with a pasted key.
- Telegram: command replies and approvals survive a restart or a failed
  write; one reply lane per chat; a cleared or compacted chat cannot be
  overwritten by an older index patch.
- Chrome: the relay verifies the browser that launched it by code signature;
  Enter in a text area inserts a newline, Ctrl/Cmd+Enter submits; disabled
  fields inherited from a fieldset are respected; navigation is reported
  settled only when it is quiet.
- Presence and loops: unlock and wake publish "present" immediately; scheduled
  jobs re-arm on a clock or time-zone change; a Slack ping can no longer block
  reconnection; a studio source failure is a failed run, not a decline.
- Providers: saving a default model during a token refresh no longer discards
  the rotated token; sign-out touches only the requested credential root;
  a malformed usage number cannot crash the app; Codex runs through
  `codex exec`; malformed tool-call sets are dropped whole with a note.
- Memory and mind: a dream's mood integration is applied once per date; the
  consolidation applied-marker rides inside the swap transaction, so a crash
  anywhere leaves one answer; the first recall packet carries both voices.
- Persistence: approval creation never evicts a pending approval; a failed
  snapshot upload is retried while content is unchanged; snapshot bytes and
  their version are read as one state; a backup restore raises every
  restored session's version above anything the phone has seen.

## Plumbing
