# NativeAgent 0.4.13

A tightening pass on top of 0.4.12. Everything that needs a model now goes
through the Providers picker: a bot answers on your iPhone with its own model,
making an image runs on the provider you chose for Work, and reading aloud asks
the provider Chat runs on. Bots read the Autonomy switch at the moment each run
starts and say plainly when a run was held. Plus a set of fixes for people
coming from 0.4.11.

## Bots

- **A bot opened on your iPhone answers as that bot.** It runs on the account,
  model and Think level the bot was made with — the ones its card shows. Until
  now a bot session continued from the phone ran on Chat's model instead, and a
  bot whose account had been disconnected, or whose model is no longer offered,
  ran anyway on a route nobody had chosen for it. It now refuses and says what
  it needs, exactly as it does on the Mac.
- **The Autonomy switch is read at the moment a run starts**, not once at the
  top of a pass. A run is a model turn long, so a switch turned off, or a bot
  paused, while earlier work was still going used to be invisible to everything
  admitted after it. Each occurrence also re-reads the bot's own definition, so
  an edited schedule is honoured from the edit.
- A bot woken by an event is checked against Autonomy again when its run is
  admitted, not only when the event arrived. With Autonomy off, the event is
  recorded as held and nothing runs — including a request that was waiting
  behind other work, or that survived a restart.
- **A run that could not start now says why.** A bot whose model has been
  retired or whose account is disconnected is recorded as a blocked missed run,
  with the reason in the same words the card uses; a later completed run clears
  it. Before this the card simply kept showing the last good result.
- A malformed request to make or change a bot comes back to the agent as an
  ordinary error instead of raising an approval card for something that could
  never have been saved. The schedule field also names all three of its shapes
  with an example each.
- A run that fails after you approve it now shows as a failure on the bot's page
  and the page reloads to show it, instead of reading as "completion not
  confirmed".

## Chat

- **Reading aloud runs on Chat's provider.** The cloud voice used to be wired
  straight to one company's speech service with the voice model written into the
  app, whatever you had chosen in Providers. It now asks the provider Chat runs
  on. If that provider has no cloud voice, one line says so and the Mac voice
  reads instead — the on-device voice is unchanged, and nothing is sent to a
  provider you did not choose.
- A press from assistive technology on another page no longer lands invisibly in
  the chat box. Chat stays loaded in the background, but while it is hidden it
  takes no presses and offers nothing to a screen reader.
- A replayed conversation no longer shows an earlier tool run as a
  receipt-shaped label. It reads as an ordinary sentence, so the agent stops
  copying the receipt shape into its own prose.

## Providers

- **Making an image runs on the Work group's provider.** Image generation used
  to go to Codex whichever provider you had chosen, driven by whatever model
  that tool defaulted to, with the image model written into the app. It now
  asks the provider you chose for Work, drives the run with that group's model,
  and takes the image model from that provider's own catalog. A Work provider
  that makes no images refuses in one plain line naming the route, rather than
  quietly sending the request somewhere else.
- No feature anywhere carries a model of its own any more: every path that needs
  one is represented in the three groups on the Providers page — Chat, Work, and
  Memory and mind — and resolves through its group.

## Upgrade fixes

- Coming from 0.4.11, a Slack delivery journal written by that version decoded
  cleanly instead of being treated as damaged, so replies that were accepted but
  not yet delivered survive the upgrade.
- Connecting a second account no longer moves Chat — and every group following
  Chat — onto that second account. The first account's choice is saved when it
  is made, and a saved choice is never overwritten.
- A conversation-summary model pinned before 0.4.12 no longer keeps running
  after the upgrade while the page shows Memory and mind following Chat. Summary
  work resolves through its group, and when nothing is set the plain mechanical
  summary stands.
- A call to a tool that is not loaded is refused on every path, including calls
  that need no approval. One gate now runs at the top of every dispatch instead
  of only in front of the approval card.
