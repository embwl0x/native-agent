# NativeAgent 0.4.16

Setup that tells the truth. The Chrome extension is easy to find and Trust says
whether it is really connected, connecting an agent in Work mode explains
itself, and conversations reuse their prompt cache from the first call.

## Chrome

- **Set up Chrome** puts the extension in a plain folder in your home folder,
  shows it in Finder and opens Chrome's extensions page. Three steps from
  there: Developer mode, Load unpacked, choose the folder (or drag it onto the
  page).
- **One live status line** in Trust: off, on but the extension is not loaded
  in Chrome yet, loaded but Chrome is not connected right now, or Connected.
  It updates the moment the extension connects. The extension is a separate
  step on each Mac and does not sync with your Google account, even though the
  purple NativeAgent tab group can.
- The Chrome block now sits with the access presets.

## Other agents

- In Work mode, "Connect to Codex" writes the entry and then says plainly that
  checking the link means running that agent here, which needs Builder or Full
  Mac. It no longer blames the other agent.

## Onboarding

- The suggested agent name is a real value you can keep or type over. If
  Continue is dim, a line says what is missing.

## Under the hood

- Within a conversation the offered tool list only grows, so a turn that loads
  nothing new reads its prompt from cache from the first call.
- The Prompt Prefix Cache health check no longer fails a fresh install over
  tiny helper calls, and explains the misses that follow a real change.
