## Audit result

Five controls do not control their advertised runtime behavior. `consolidation_enabled`, `auto_promote_consolidated`, `adaptive_promotion`, and `cross_session_recall` have no production consumer; `knowledge_graph_enabled` and `hygiene_enabled` are read only by presentation/status code, not by the systems they claim to control.

TrustCenter’s defaults and policy normalization are storage/schema handling, not behavioral consumers.

## Ranked defects

1. **Knowledge Graph off is not an authority gate.** Inject the checked policy value into MemoryV2’s KG hook, rebuild/backfill, graph tools, UI loading, and recall enrichment so `false` stops all graph production and use.

2. **Cross-session recall cannot be disabled.** Freeze `cross_session_recall` with chat admission and skip both ContextFlow memory atoms and TurnEngine’s automatic root-wide recall when it is false.

3. **The “Nightly memory consolidation” switch is a dead weekly-loop key.** Make `MemoryConsolidationHygieneRunner` read checked policy before staging, and rename the row to weekly unless a real nightly owner is introduced.

4. **Adaptive promotion ignores its switch.** Pass a fresh checked `adaptive_promotion` closure into the production promoter and return before turn observation when disabled.

5. **Auto-promote consolidated memories ignores its switch.** Pass `auto_promote_consolidated` into candidate construction and suppress the durability auto-accept branch when false.

6. **Memory hygiene off only changes a status label.** Gate the cleanup portions of the scheduled/approved hygiene path on `hygiene_enabled`, or remove the separate switch if consolidation and hygiene are intentionally inseparable.

7. **The embeddings switch can go stale after an external backend change.** Subscribe Setup to the embeddings config/runtime invalidation and call `refreshEmbeddings`; the current one-shot `.task` refresh is insufficient while the view stays mounted.

No files were edited and no build or tests were run.
