# NativeAgent Data Bounds

Selected live limits enforced by the Swift runtime. These are store-specific
policies, not a global disk quota. Paths are relative to the app's data root.

| Store | Limit | Enforcement / owner |
|---|---|---|
| Phone presence evidence | 64 place events and 64 sense/setup events; each organ's latest setup and observation and the first movement since physical Mac input retained within the cap | Atomic histories in `mobile/place-events.json` and `mobile/sense-events.json`; bridge-only writers. Motion, Focus, charging, battery, app audio route, network path, Music metadata, scoped photo count and Places setup use the same sense owner. Current inference requires evidence within 15 minutes; history is not current presence. Each phone owner holds at most 128 pending changes and sends at most 8 per publication. See [mobile presence](mobile_companion.md#where-the-person-is). |
| MemoryV2 memories | 2,000 rows by default | Value/lifecycle rank, then least recent use; pinned/identity rows evicted last. `MemoryV2+Storage.swift` |
| Approvals | 300 records | On overflow, orphan pending requests unanswered for 24 hours since their last request (creation if never re-asked), then evict oldest eligible terminal records; refuse creation if insufficient space remains. `ApprovalStorage.swift` |
| Chat hot index | 200 sessions by default, protected sessions excepted | Canonical transcripts and locator rows move to durable `chat/archive/`; no automatic expiry. `ChatSessionRetention.swift` |
| Chat streaming tail boxes | Cache target 8; active or consumer-held boxes protected regardless of count | On cache demand, `TranscriptsFacade` prunes only unreferenced boxes outside active streaming rows. Mounted bubbles and scroll observers retain the same box through their observation lifetime. `ChatStreamingTail.swift` |
| Chat compaction recovery copies | 5 per session; recent tier 30 days, 200 sessions, 128 MiB | Pending distillation sources are protected. Admissible retiring copies share one exact-line union, durable write and verification in `chat/archive/originals/<id>.jsonl` per session operation. Unknown/corrupt sources stay in recovery; deletion requires verified coverage. `ChatCompactionStorage.swift`, `ChatCompactionBackupRetention.swift` |
| Chat context window | Selected provider/model's detected catalog window, limited by the person's Custom cap; Settings > Context window > Compact at N% sets one whole percentage 30–95%, default 85%, for foreground and background folds; effective trigger min(configured percent × window, window − actual request output allowance); measured target min(configured percent × window × 55/85, window − that same allowance) | `chat.compaction_percent` through setting.get/set shares `nativeagent.contextWindowCompactionPercent` with Settings; invalid saved values visibly fail. The ring shows the last matching provider receipt's observed input usage; missing usage/window measurements are unavailable, and unmeasured transcript/prompt shares stay unknown. Compaction sizes the next request from the real builder's final characters, calibrated by that receipt's characters/input tokens. The saved plan references exact user-row delivery; live Regenerate cuts belong to its request builder. Saved-plan sizing clears completed-turn cuts and includes its answer, receipts and saved words once. Whole-transcript replay has no aggregate character or row-count ceiling; only recollection folds move its head. Per-row caps remain. The old `chat/prefix_window/*.json` files are unused and untouched. No 128k reserve ceiling remains. Pure sizing never consumes contacts or starts model work. Without a matching receipt/plan, manual compaction labels its history estimate; automatic aging waits for built-request evidence. Every live request is checked again before send; estimated built-request input plus adapter-owned wire output allowance above the window refuses as `context_window_exceeded`, never truncates. Sizing counts are estimates, not tokenizer guarantees. Unavailable recollection refuses preparation; unreadable evidence reports its failure. `SessionContextMeasurement`, `ChatSessionAutocompactionConfig` |
| Chat recollection blocks | Each body is asked for 1/5 of its rendered source chunk (at most 32,000 source characters); the allowance is the prompt's ask, and any non-empty block is kept as written, plus block-local receipt/card notes; existing history read allowance 40,000 characters | Raw folds and rollups select the same replay-visible rows, mapping back to preserve hidden rows wherever they occur; raw dream-safe source folds first. Completed folds continue toward the configured target capped by room for the actual request output allowance (default min(55% of window, window − allowance)), including retained blocks. Protected turns/cards or no progress report why the target cannot be reached. Chunks distill concurrently and append atomically in source order. A leading replay-visible recollection run above 10% of the window and 8,000 characters may roll up a dream-safe group larger than 8,000 characters as part of that pursuit. See [Turn resilience](https://github.com/embwl0x/native-agent/blob/main/docs/TURN_RESILIENCE.md#8-context-compaction). |
| Cognitive active nodes | 256 by default | Configured by `CognitiveConfiguration.swift` |
| Cognitive artifacts | Derived from node and reflection budgets; minimum 64. Cares, their migration marker, retired preserved families and reflection receipts still owing effects or dream-journal acknowledgment are excluded. Owed receipts also bypass the settled reflection restore cap. | `CognitiveSubstrate+Persistence.swift` computes the cap; `CognitiveSQLiteStore.swift` prunes by artifact family |
| Shared traces | 5,000-row trigger → 4,000 retained; 8 MiB → 4 MiB | `traces/events.jsonl`; path-owned append policy |
| Activity events | 5,000-row trigger → 4,000 retained | `activity/events.jsonl`; retains a sample of rare event kinds |
| Shared-folder search | 50 results overall; 2,000 files per workspace; content search up to 512,000 bytes per file | `Connectors.swift`; `unexamined` names the current workspace's unsearched remainder when a bound stops its walk, and each later workspace skipped at the result cap. The same coverage makes the activity receipt `partial`; a per-workspace scan cap still permits searching later workspaces. |
| Daily turn traces | 12 MiB → 8 MiB; 14 days | `TurnTrace` append and date-based retention |
| Browser observations | 128 MiB, 256 capture groups, 7 days | Enforced on capture writes by `BrowserCaptureCache.swift` |

Row triggers on the amortized trace/activity feeds can overshoot by up to 127
rows between checks. Browser artifacts and diagnostic traces can expire;
recapture or reread the source when needed.
