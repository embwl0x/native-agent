# Intended changes: the permission law

Every row of `baseline.txt` that the law changes, each explained by the law in one line. Produced by running `PermissionsSnapshot` on this branch and diffing against `baseline.txt` (the same harness on the code before the law):

```
swift build --package-path Modules/NativeAgentCore --product PermissionsSnapshot
Modules/NativeAgentCore/.build/debug/PermissionsSnapshot > after.txt && diff baseline.txt after.txt
```

13,272 of 14,022 rows differ; every differing row is explained by one or more of the lines below (its own-turn decision, its sub-agent columns, its class column), and no row changed outside them. A row is one tool or door action, with one input, under one posture (full_mac, work, read_only), one steer (person, trusted_agent, untrusted_peer) and one switch state (all integrations on, or every write switch off); it shows the decision on six surfaces (chat, workshop, synth, swarm, bot, desktop). Each tool and door action runs with no arguments, and again with every example input its own contract takes: a path inside their workspace and one beyond their roots (`<outside>`), a copy or move from them workspace to beyond, a dry run, a direct endpoint; a door action also runs with each read condition its row declares, a broken one, and its preview.

**The line.** Their side: their data root and Trust's workspace roots (their scratch, their worktrees, their abilities and bots, their chats and memory, their Desk and Make, and their Chrome extension's tabs). User's side: a path beyond those roots, their accounts and integrations, their Mac's apps, settings and permissions, another app's settings, a shared remote, any command line (shell, bash, git: nobody knows what a line reaches, and the law never reads its text), and anything whose declaration does not say where it reaches. Destructive is declared once, on the tools that are permanent deletes by nature. Safe changes nothing on their side. Work asks before anything on their side.

## Not in the harness

- `agent_message`, `agent_read` and `workspace` refuse in every row before and after (the stub has no saved contact or session); `agent_message` is declared `send`, and its dry run is a write.
- The stub refuses a call whose integration switch is off, reading the gate table; for the code before the law it also reads the three tools that code gated only inside its dispatcher (`mobile_notify`, `phone_request`, `mail_save_attachment`), so the baseline shows what that executor did.
- One answer per call: SecurityCenter resolves the call's roots, effect profile, class and reach once and the gate uses that answer; the law by name now serves only name-only questions (the catalog, the planner). So an `agent_message` dry run (a write) no longer cards in Work as a send; the stub has no saved contact, so its rows refuse before and after.
- `chat.clear`, `history.clear` and `mind.clear` are theirs in every posture (they were the owner's below Full Mac): their chats, their recorded activity and their thought store are their own tidying. The door's owner refusal is not in the harness, so no row shows it.
- One resolver: `PermissionLaw.answer` gives the effective level (the law, then User's saved entries for the tool, its capabilities and the old tool a door action runs) to SecurityCenter, Trust's by-name answer and the Workshop executor alike.
- A saved autonomy entry that is not a level (`"browser.chrome_click": false`) makes the saved policy malformed: Trust rejects it and every call fails closed, as for any malformed policy. The harness asserts this under Full Mac.
- One of them parts reaches what its own manifest declares: beyond their data, model and localhost, or a dependency that changes their side. A part declaring only `app_data_write` acts in Work and Safe. The harness authors no parts, so no row shows it.
- A Workshop step the law asks for refuses before any card when its Mac Integration switch is off, from the same gate table and switch readiness the chat gate uses; the harness does not run the executor.
- A swarm worker runs under the file access of the chain that started it (bound per call by the file-access gate), so a caller fenced to read-only or none cannot hand a write to a worker; with no fence the worker has exactly what they have.
- A Workshop step is judged, carded and replayed as the call that runs: a folded door action (`app {action: "contacts.delete"}`) is its tool, so it cards before it runs and the approval binds that exact tool and arguments.
- Command text is read nowhere. The peer floor (an untrusted peer steered the turn) judges a shell or git call by its declared reach: below Full Mac every shell, git or process call still cards there; under Full Mac it is their call unless it names a path under persona/. What the floor no longer sees under Full Mac: a peer-steered shell or git line that deletes (rm, git clean, reset --hard, push --force) or resets macOS permissions (tccutil, TCC.db) used to card for that reason and now runs. On them own turns under Full Mac those deleting lines already ran; a permission reset inside a shell line asked there too, and now runs as a shell call (User's ruling).
- The proof binds the engine's steer check (`PeerTrust.install` binds `CapabilityLifecycle.turnWriteCheck` to PeerDataTaint), in the baseline too: on an untrusted peer's turn the ability lifecycle actions (sense, skill and tool make, drop, restore, quarantine) refuse in every posture, before and after, as the app does.
- Every call is judged as if its arguments were valid. A file tool given no path at all (`copy_file {}`) is judged on what it names, which is nothing on their side, so it passes the gate; the tool itself refuses it for the missing path.
- User's saved Trust entries: the harness saves none. They still bind, tighter only (below Full Mac the stricter of their entry and the law; under Full Mac only their `blocked`). A saved entry can no longer loosen a tool past what the law gives.
- Workshop plan steps: the planner's own map is gone. Each step asks Trust with its own arguments: a step the law acts on runs, one it asks for waits on a card (a destructive one even under Full Mac), one it refuses fails with "Trust refuses <tool> in User's current posture; nothing ran.", and a Trust read error fails the step with its reason; the planner prompt no longer carries `[autonomy=…]`.
- MCP and authored tools: a mounted MCP tool is a read only where its row says so (SearXNG search), else a write; a part is the most any call or permission it declares reaches.
