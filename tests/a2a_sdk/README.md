# Official SDK interoperability

After `swift build --disable-keychain --package-path Modules/NativeAgentCore`
and `swift build --disable-keychain`, run:

```sh
uv run --no-project tests/a2a_sdk/run.py
```

The runner creates a virtualenv and HOME under system temp, installs
`a2a-sdk[http-server,grpc]==1.0.0` and `uvicorn==0.53.0`, starts loopback peers,
and runs the Swift client tests followed by the in-process Swift server tests.
All peer processes are stopped afterward. App data, HOME and credentials are
isolated under system temp.
The harness pins protobuf to `>=6.33.5,<7`: SDK 1.0.0's REST query parser uses
`FieldDescriptor.label`, removed in protobuf 7.
The SDK's compatibility imports require its grpc extra even for JSON-RPC.
It covers 1.0 JSON-RPC, 0.3 compatibility JSON-RPC, 1.0 HTTP+JSON, and 1.0 gRPC.
The fourth peer uses the official SDK GrpcHandler and generated A2AService.
The test executor uses the official default handler, task store, route factories,
serialization and compatibility adapter. A small outer wrapper enforces a unique
temporary bearer per peer and deliberately closes one stream after a working
event. The server proof then starts an ephemeral loopback listener using the
production authenticated contact routes, wire mappings, task owner and SSE
writer. Only the turn producer and credential lookup are synthetic. The SDK
acts as the client for all eleven 1.0 operations over JSON-RPC, HTTP+JSON and gRPC,
and for the existing 0.3 compatibility transport.
It checks text, embedded files, scalar/array data, peer isolation, rejected auth,
version rejection, filtering, cursor pagination, authenticated extended cards,
push config CRUD, send-time push configuration, and authenticated completion and
cancellation push delivery to a temporary loopback webhook.
Notification bodies are strictly decoded using the SDK StreamResponse schema.
It also rejects insecure and metadata/link-local webhook URLs.

Scenarios: send, nonblocking task followed by polling, successful stream,
interrupted stream, input/auth required, cancellation, incompatible card and
credential revocation. A2A task completion is distinct from a message reply.

Pinned fixtures are generated by `capture.py` using the SDK's server serializers
and 0.3 conversion functions; their payloads are not hand-written. To reproduce,
run that script in the same temporary SDK environment with `tests/a2a_sdk/fixtures`
as its only argument. Fixed IDs/text are synthetic test input, not wire edits.
Normal Swift tests read these fixtures without requiring Python or network access.

Sources read for the mappings:

- [A2A changelog, including 1.0.1](https://github.com/a2aproject/A2A/blob/main/CHANGELOG.md)
- [A2A specification](https://a2a-protocol.org/latest/specification/)
- [Official SDK 1.0 migration](https://github.com/a2aproject/a2a-python/tree/main/docs/migrations/v1_0)
- [Pinned SDK source](https://github.com/a2aproject/a2a-python/tree/v1.0.0)

The protocol patch version 1.0.1 negotiates as `1.0`; the independently pinned
SDK package version is `1.0.0`.

The app serves `SendMessage`, `SendStreamingMessage`, `GetTask`, `CancelTask`,
`SubscribeToTask`, `ListTasks`, `GetExtendedAgentCard`, and create/get/list/delete
push config operations over JSON-RPC at `/a2a` and HTTP+JSON under `/a2a/`.
REST responses use `application/a2a+json`; streams use SSE. The card advertises
all three 1.0 bindings and the existing 0.3 JSON-RPC compatibility interface, streaming,
push notifications and an extended card. Every route is bearer-authenticated.
A card request carrying `A2A-Version: 0.3` receives legacy card/security shapes.
Legacy slash methods still work without a version header. Explicit version
headers must match the method family. The third 1.0 binding serves the normative
A2AService over gRPC on its own loopback-only port, advertised as a GRPC interface
in the card. gRPC uses the same contact bearer in authorization metadata.

ListTasks returns only the authenticated contact's tasks retained in this run
(up to 128), sorted by last update descending, with context/status/timestamp
filters and cursor pagination. Artifacts are omitted unless requested. History
is not exported (a permitted lower server limit of zero). Task execution,
cancellation settlement, local-only access and bearer/peer checks are unchanged.

To call a running app, set `A2A_BASE_URL` to its actual loopback base URL and
`A2A_BEARER_TOKEN` to the contact's bearer token, then run:

```sh
A2A_BASE_URL='http://127.0.0.1:BRIDGE_PORT' A2A_BEARER_TOKEN='CONTACT_BEARER' \
  uv run --no-project tests/a2a_sdk/call_live_server.py
```

The script discovers the gRPC port from the card, permits that separate port only
on the same loopback host, and supplies the bearer through the official SDK call
context. It reads no local configuration and prints each card/reply/event/list
result. It creates three conversation tasks per binding and cancels the third.
The script runs an ephemeral loopback webhook, registers its bearer-authenticated
push config, verifies the cancellation notification, and deletes the config.
Use a local running app so it can reach that loopback webhook.
If a live task finishes before cancellation, the server correctly refuses to
cancel the terminal task and the script reports that failure; it does not claim
a successful cancellation. This is an owner-run live check, not an installer.
